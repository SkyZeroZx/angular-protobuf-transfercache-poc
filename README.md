# Angular `HttpTransferCache` binary POST collision

This is a small Angular SSR reproduction for binary POST bodies in `HttpTransferCache`.

It exposes the same Protobuf RPC flow on two pages:

| Page                                                | Request body  |
| --------------------------------------------------- | ------------- |
| [`/blob`](http://localhost:4200/blob)               | `Blob`        |
| [`/arraybuffer`](http://localhost:4200/arraybuffer) | `ArrayBuffer` |

Each page sends three sequential requests to the same endpoint:

```text
1. document 100, TransferCache enabled
2. document 200, TransferCache enabled
3. document 200, transferCache:false
```

The request bodies contain different Protobuf bytes:

```text
document 100: 0864
document 200: 08c801
```

Published Angular `22.1.2` replaces both non-string bodies with an empty string while building the cache key. The second request can therefore receive the response for document `100` without reaching the origin.

## Run the vulnerable version

```bash
npm ci
npx playwright install chromium
npm run build
npm run validate
```

`npm run validate` opens both pages and expects the collision on both body types.

The project uses schemas generated by Buf, `@bufbuild/protobuf`, a real Express endpoint, production SSR, and Playwright Chromium. Validation records the raw SSR result, hydrated DOM, browser POSTs, exact wire bytes, and origin calls.

This demonstrates response confusion inside one SSR/hydration TransferCache lifetime.
